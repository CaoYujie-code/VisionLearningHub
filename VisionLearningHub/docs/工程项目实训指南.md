# 工程项目实训：把算法写成能交付的程序

0.7.0 在44道基础题之外提供9个完整工程、45个可验证任务块；另有37个专属小任务、9组对比实验和9道维修练习。详见[本版导航与工程深入学习指南](导航与工程深入学习-0.7.0.md)。双模式与新案例见[双模式工程学习指南](双模式工程学习指南-0.6.0.md)。它们使用真正的图片文件和普通Python模块，验收读取你输出的JSON、标注图和校正图，而不是只调用一个固定的 `solve()` 函数。

## 从哪里开始

更新插件并重载窗口后，进入 **工程项目 → E01 批量硬币计数与定位**。先读“任务与素材”，再到“代码与运行”选择文件。VS Code 中点击“打开选中文件”；网页版可直接编辑多个文件并添加根目录Python模块。

每个工程都有5个阶段。阶段勾选和复盘笔记保存到本地；只有正式验收通过才计入代码进度。主文件、辅助模块或配置变化后，需要重新验收。

## 首批四个工程与训练目标

| 工程 | 实际工作 | 你要交付 | 验收重点 |
| --- | --- | --- | --- |
| E01 批量硬币计数 | 扫描目录、读图、分割、定位、计数、处理坏文件 | 数量、中心坐标、定位叠加图 | 每图一条记录；无漏检与重复；中心误差≤8px |
| E02 表面缺陷检测 | 读取已对齐模板，补偿曝光差，提取局部异常，决定放行 | 缺陷框、accept/reject、标注图 | 缺陷一对一IoU≥0.5；正常图不能误拒收 |
| E03 单据透视校正 | 检测纸张、排序四角、透视变换、批量保存 | 四角、240×320校正图、定位图 | 四角误差≤7px；校正图平均像素误差<24；空桌面返回无目标 |
| E04 过线计数 | 按时间顺序读帧、检测、关联、保留ID、记录双向事件 | 每帧目标ID与中心、过线事件、可视化 | 位置≤6px；身份连续；不重复计数；事件时间允许±1帧 |

前三个工程的每个批次含4张有效图片和1个损坏文件。跟踪工程每批12帧；包含双向运动、短时目标缺失和静止目标。每个工程正式验收5个批次，共20个批次。

## 工程目录

VS Code 工作区中的项目位于：

```text
.vision-learning/projects/E01/
  main.py          # 普通CLI入口
  imaging.py       # 由你实现文件读取与图像保存
  pipeline.py      # 由你拆分算法、批处理和结果写入
  config.json      # 运行参数
  detector.py      # 例如你自己增加的根目录模块
  data/sample/     # 公开开发图像与说明
  README.md
  SOURCES.json
  ASSET_NOTICE.md
```

你可以自由命名内部函数，例如 `load_frame()`、`segment()`、`extract_regions()`、`associate()`、`draw_results()`。可以改写主流程，使用普通 `import detector` 组合代码；不需要导入平台的辅助函数。平台源码快照包含根目录最多32个 `.py` 与 `config.json` 文件，总量不超过100000字符。文件名采用小写字母、数字和下划线；嵌套Python包与额外自定义数据文件目前不纳入平台源码快照，请在导出的工程中自行组织。

提供的 `main.py` 使用 `--input`、`--output`、`--config` 参数。验收只要求这个CLI能执行并生成约定的结果，不限制检测算法或函数拆分。打开“查看参考工程”可逐文件对照，平台不会自动填入或覆盖你的代码。

## 推荐实施顺序

1. 写输入输出清单：有哪些文件，坏图如何处理，坐标和时间的单位是什么。
2. 先实现 `imaging.py`，确认中文路径、空输入和解码失败处理正确。
3. 只处理一张开发图，保存中间结果；解释它在哪些条件下可能失败。
4. 封装自己的函数，再加入目录遍历、配置读取和JSON序列化。
5. 点击“运行开发样例”。这一步允许反复调参，不计通关。
6. 点击“多场景工程验收”，阅读每个批次中逐张图的检查项，定位到具体函数。
7. 在“复盘与历史”记录：输入条件、参数选择、失败样例、改动模块、下一次实验。
8. 导出工程，用独立命令行和自己的图片验证。

不要直接写固定数量、固定坐标或跳过文件的输出。空场景、不同数量、曝光变化、坏图和时序事件都会单独检查。参考实现只是一个基线，例如E02没有解决真实配准误差，E04最近邻关联没有解决复杂遮挡；可以在自己的工程里继续扩展。

## 在VS Code、PyCharm或终端运行

“导出工程与素材”包含当前源码、开发图片、5组验收输入、参数和来源说明。它不依赖平台运行；已有Python/OpenCV/NumPy课程环境时无需重新安装。

```sh
python main.py --input data/sample --output output --config config.json
python main.py --input data/holdout/101 --output output_101 --config config.json
```

缺少依赖时，在单独的虚拟环境中安装导出目录的 `requirements.txt`。在PyCharm中选择同一个解释器，将工作目录设为工程根目录，在main.py运行配置中填写上述参数即可。VS Code中的“终端运行工程”和“调试工程”使用当前真实文件；调试需要用户自行安装Python Debugger。

导出的是源码与课程内置素材。你自己额外放入的图片、嵌套包和外部依赖请单独保存，并纳入你自己的工程版本管理。

## 使用自己的图片

- E01、E03支持平台内上传PNG/JPEG探索，结果明确标为“没有人工真值”，不会计入正式通关。
- 全部工程都可导出后用 `--input` 指向自己的PNG目录。
- E02需要同目录 `_reference.png`，且它与待检图尺寸一致、已经对齐。
- E04需要 `_sequence.json`，包含 `frames`（每项含file和timestamp_ms）以及 `line_x`。顺序以清单为准，不靠文件名猜测。
- E01–E03忽略下划线开头的辅助文件，并把损坏图片记录为 `decode_failed`，继续处理其余输入。

建议逐步补充自己的暗光、反光、遮挡、相机偏移样本，并人工标注。仅有课程自动通关，还不足以说明在你的设备上能稳定运行。

## 图像来源与场景真实性

三张上游PNG固定到scikit-image v0.25.2并校验SHA-256，打包在插件中；运行不需要联网，也不需要安装scikit-image。

- `coins.png` 来自Brooklyn Museum Collection，经scikit-image分发；上游说明是“无已知版权限制”，不是明确标注的CC0。[来源说明](https://github.com/scikit-image/scikit-image/blob/v0.25.2/skimage/data/_fetchers.py)
- `brick.png`、`gravel.png` 的原始纹理来自CC0Textures（现ambientCG），上游明确标为CC0，scikit-image版本已做裁剪与变换。[来源说明](https://github.com/scikit-image/scikit-image/blob/v0.25.2/skimage/data/_fetchers.py)
- 缺陷、单据内容、透视和运动序列由平台生成，均为教学变体；它们不是实拍工厂缺陷、真实票据或独立相机视频。
- 标注来源：硬币中心由本项目人工记录并按裁剪/翻转变换；缺陷位置、单据四角及运动轨迹来自生成参数。评分不调用学生的检测函数生成真值。

完整来源、下载地址、摘要与许可说明见项目内 `SOURCES.json`、`ASSET_NOTICE.md`，仓库维护脚本为 `tools/fetch_engineering_assets.py`。

## 保存、恢复与清除

源码快照、阶段记录、复盘、历史与验收图继续使用已有SQLite和ZIP备份机制。VS Code中的真实源文件始终为准。恢复备份时，工程源码暂存在 `data/restored-code/<批次>/E01.project.json` 等文件供人工比较，不覆盖当前工程。

清除学习记录会保留项目源码和项目样例文件。新工程不提供一键覆盖重置；需要重做时先导出备份，再编辑对应模块。源码变更影响当前验收状态；阶段勾选仅表示个人实施计划，不代表算法已通过。
