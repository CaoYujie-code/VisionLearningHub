# 插件更新与发布

## 学习者：在插件内更新

首次安装带更新功能的 0.3.1 后，后续更新不需要手动下载和导入 VSIX。

1. 插件激活后按 24 小时间隔检查本项目的 GitHub Releases。
2. 发现更新时显示版本提示，点击“更新”。也可以按 `Ctrl+Shift+P` 执行 **Vision: 检查插件更新**。
3. 插件下载、校验安装包并交给 VS Code 安装。保存文件后按提示重载窗口。
4. 源码、学习笔记与进度保留，更新缓存随后删除。

设置 `visionLearning.checkUpdates: false` 可关闭自动检查；手动检查仍然可用。点击“稍后”会跳过该版本的自动提示，手动检查不受影响。取消下载或网络失败时继续使用当前安装版本。

0.3.0 不含更新入口，需要先安装一次 0.3.1。尚未发布到 Marketplace 时，这个 GitHub 更新渠道仍可工作；上架时应保持相同 publisher 和扩展 name。

## 仓库访问与校验

公开发布版本通常无需登录。仓库为私有或当前授权不足时，手动检查会提供“登录 GitHub 并重试”，使用 VS Code 官方 GitHub 认证；账号必须有该仓库读取权限。自动检查不会强制弹出登录。

仅使用固定的 `CaoYujie-code/VisionLearningHub` 发布源，跳过草稿与预发布，不自动降级。安装前验证：

- 发布版本号与 VSIX 文件名。
- GitHub 提供的 SHA-256 digest 与实际下载内容。
- ZIP 内 `extension/package.json` 中的 publisher、name 和 version。
- 包大小与下载限制。

下载跳转到 GitHub 资源主机时，不向其他主机转发 GitHub 访问令牌。令牌只由 VS Code 会话读取，不写入工程、日志或版本库。

当前正式支持桌面本机 VS Code；远程 SSH、WSL 与浏览器版的扩展更新尚未完成验收。发布源暂不可访问、账号权限不足或缺少校验值时，会保留当前版本并提示原因。

## 维护者：发布一个新版

在内层应用目录执行：

```powershell
python tools/set_version.py 0.3.2
npm ci
npm ci --prefix extensions/vscode
npm run check
npm run build
npm --prefix extensions/vscode test
npm --prefix extensions/vscode run package
```

版本脚本只同步版本文件，不提交或发布。检查本次功能与 CHANGELOG 后，在外层仓库提交并推送：

```powershell
git add .
git commit -m "feat: describe the actual change"
git push origin main
git tag v0.3.2
git push origin v0.3.2
```

`.github/workflows/release.yml` 会验证标签与插件版本一致，执行回归、构建 VSIX、生成校验文件，然后发布到 GitHub Releases。工作流使用 GitHub 自动提供的仓库令牌，不需要在源码中添加个人令牌。仓库需要启用 GitHub Actions，并允许该工作流写入 Releases。

发布完成后，到 GitHub Releases 确认安装包和 SHA256SUMS.txt 都存在。插件从 GitHub API 的 asset digest 读取校验值，不能只上传一个没有 digest 的链接。不要用预发布标签代替正式稳定版。

该工作流没有执行 Marketplace 上架。以后接入 Marketplace 时，需另行配置发布者身份与凭据。

## 验证方式

- `npm --prefix extensions/vscode test` 覆盖版本、包来源、大小、摘要、身份、重定向和未授权错误。
- `tests/run_vscode_host.py` 使用独立配置、独立扩展目录，验证真实官方安装命令；测试更新包仅存在临时目录，不发布为正式版本。
- 本机测试结果不能替代远程 Actions 发布成功状态；以对应标签的工作流和 Releases 页面为准。
